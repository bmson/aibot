# Read-only production source snapshot

The manual **Export PostgreSQL workspace snapshot** workflow runs a consistent, read-only PostgreSQL export inside a Cloud Run job. The database URL is injected from the existing Secret Manager secret into that job; GitHub Actions receives only non-secret source and embedding identifiers. The job uploads one complete v3 migration bundle to `gs://<project>-workspace/workspace/<installation>/migration/snapshots/<execution>.json` using its Cloud Run service identity. An object-generation precondition prevents a rerun from overwriting a live snapshot. Its log summary contains the bundle checksum, byte length, SHA-256, record count, and object URI, but no records or credentials.

Run this workflow from `main` only after the matching commit has finished the normal production release. Supply the PostgreSQL owner agent UUID, the **source** embedding provider/model/dimensions/revision, and the target Firestore database ID. The launcher refuses to run if the released migration image does not have the exact commit SHA, if the workspace bucket differs from the project-owned bucket, or if the input identities are malformed. A new execution writes a new object; it does not replace the prior export.

This is a rehearsal export while PostgreSQL remains writable. It does not import records, activate Firestore, or authorize PostgreSQL deletion. Before a final cutover, freeze source writes and active work, export again, verify complete table and per-record parity plus object inventory, exercise the application against Firestore with PostgreSQL offline, test restore, and confirm the live runtime has no database-secret dependency. Follow [the cutover checklist](firestore-cutover-checklist.md) for the acceptance gates.
